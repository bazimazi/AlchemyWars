# Specification coverage

This maps every numbered section of the supplied specification to the implementation and its evidence. "Implemented baseline" means the system has working code, not that every illustrative example is a separate promised feature. The plan explicitly makes monetization/gacha optional and asks for content to grow after validation.

The software meets the numerical MVP content counts and implements many later systems, but it does not yet implement the full specification. The concrete gaps below supersede earlier broad baseline claims. Automated verification does **not** establish 5-10 hours of human campaign playtime, physical-device 60 FPS, long-term fun, retention, every possible balance matchup or commercial service readiness. Those validation targets remain explicit below. Operating future seasons is ongoing work rather than a finite code deliverable.

## Remaining implementation work (audit after TypeScript migration)

- **Guild systems (41):** knowledge donations, shared known discoveries, research tiers, raids and standings exist. Element donations, explicit guild missions and a collaborative hidden-reaction experiment project with contribution targets are missing.
- **PvP modes (38):** ranked asynchronous duels, draft duels and guild wars exist. Dedicated Element Wars and weekly competitive challenge rules/standings are missing.
- **Codex and profile (27, 28, 80, 84, 85):** elements, recipes, statuses and the graph exist. Dedicated creature/artifact encyclopedias, a persistent discovered-chain catalog, full collection-card relationship counts and highest-boss profile display remain incomplete. Lore exists in element details and campaign memories rather than a complete codex section.
- **Unit architecture (17):** element slots, passives, relics and simple casting priorities exist. Separate configurable ability slots, per-unit growth-stat definitions and per-unit animation sets are not implemented.
- **Live operations (90, 108, 121):** the server can change maintenance state, season labels, announcements and one predefined mutator. New definitions still require a file release and restart; comprehensive remote balance/content configuration is missing.
- **Endgame and content depth (78, 109, 117):** procedural encounters exist but daily restrictions use four fixed templates; a general composable challenge generator and Mythic-tier discoveries are missing. The current catalog has 54 elements with no outgoing recipes; the audit detects this but does not resolve it.
- **Performance implementation (87):** deterministic bounds, indexed recipes and event queues exist. Object pooling is not implemented. Profiling must guide further optimization; physical-device 60 FPS has not been verified.

**Validation still required:** human campaign pacing (5-10 hours), physical-device performance, assistive-technology testing, long-term balance, retention and enjoyment. These are separate from the implementation gaps above.

**Optional branches:** real-money cosmetics, premium currency and gacha remain intentionally omitted; the specification does not require enabling them.

The table below records broad system coverage, not acceptance of every requirement within a section. Entries marked partial have confirmed implementation gaps.

The TypeScript migration checks all source and tests with strict compilation. Subsequent implementation work strengthened content-authoring validation, offline startup reliability, season-rating visibility and guild-war reward accounting. Evidence: `npm run verify` (122 engine/server tests and 14 browser tests).
