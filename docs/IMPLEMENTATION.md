# Implementation and operation

## Architecture

All authored game, server, tool, service-worker and test code is TypeScript. `tsconfig.json` enables strict checking, unused-import checking and no emit on errors; `tsconfig.worker.json` checks the service worker with browser-worker globals. Shared contracts live in `src/types.ts` and `server/types.ts`. Combat effects use a discriminated union. Untrusted save and pack inputs are validated at runtime. [TypeScript NodeNext modules](https://www.typescriptlang.org/docs/handbook/modules/reference) preserve `.js` import specifiers for emitted ES modules. The compiler and `@types/node` are build-only dependencies.

`npm run compile` writes private build output to `.build/`. `npm run build` publishes only compiled browser modules, CSS, assets, HTML and the service worker to `dist/`, then generates its offline asset manifest. The service worker registers as a module. `npm run dev` watches source, styles and content, recompiles changes serially and restarts only its own server process. Type errors prevent publishing a new build.

`src/data/` contains versioned element, reaction, unit, enemy, boss, status, relic, progression, environment, seasonal and story definitions. `src/core/` implements deterministic combat, indexed reactions, progression commands, runs, trials, replay validation, content authoring and saves. `src/ui/` renders the game using browser APIs and original SVG artwork. `server/` provides authenticated, authoritative progression and community operations with an atomic file-backed store.

The simulation runs at a fixed quarter-second timestep with seeded randomness. Playback consumes snapshots independently of simulation speed. Replays retain the seed, content version, formation, progression modifiers, opponent/generated encounter, arena rules and starting health. Chain depth, passive cooldowns, per-action event limits, summon limits and the 90-second battle limit bound execution. The recipe index is tested with 10,000 rules.

Effects compose through damage, statuses, healing, shields, cleanse, chain, spread, element application, explosion, resurrection, summons and transformation. Fourteen event categories can trigger passives. Conditions support status, environment, health, neighboring enemy count, target tags, shielding, mastery and account research. No individual recipe is hardcoded into the combat engine.

The client and server call the same validated progression commands. The client never submits an authoritative battle outcome, damage figure, reward amount or chosen online seed. The server snapshots an issued battle and computes its result before paying. Concurrent claims pay once. Ranked account mastery, vessel growth, research, talents and evolution are normalized. Element Wars and Weekly Crucible also remove equipment/passives and loan equal vessels with complementary weekly elemental pools. Drafted PvP loans both participants complementary pools and equal starting vessels. Guild-war claims are recorded on the account as well as the guild, preventing repeated weekly points or gold after changing guilds. Season leaderboards display reset ratings immediately, including accounts that have not played their first new-season duel.

## Local and online saves

Local schema version 1 saves are normalized on import and load. Old prototype saves receive defaults for new features. The previous healthy journal is retained as a backup. Export/import is limited to 1 MB. Invalid or stale references are repaired or removed. Active runs and campaign, run, trial and PvP replay configurations survive saving.

Account-service startup is bounded to 2.5 seconds so local play still opens when that service is unreachable. Online requests have a 10-second timeout; retrying battle settlement uses the original idempotent battle ID.

Online data lives in `DATA_DIR/world.json`, with a previous healthy `.backup`. A transaction clones state, writes a temporary file, then atomically renames it. Failed mutations never replace the database. If the primary file is damaged, the server recovers from the backup without overwriting it with the damaged primary. Both unreadable files cause startup to stop, preserving the evidence for recovery.

This storage adapter is intended for one server process and modest communities. Do not start multiple processes against the same data directory. Back up the directory while the process is stopped. For larger deployment, replace Store with a transactional database adapter before adding multiple replicas. No deployment or public service has been provisioned by this repository.

Passwords use salted scrypt hashes. Sessions use random tokens, only their hashes are stored, and cookies are HttpOnly/SameSite Strict. The HTTP boundary enforces origin checks, request limits, rate limits, a static-file allowlist and a content security policy. Administrative endpoints require a bearer secret. There is no email collection or password-reset email service; accounts are name/password accounts on the operator's server.

## Serve the production build

Run `npm run build`, then `node .build/scripts/serve.js --dist` from the repository root. A static host can serve `dist/` for offline/local play; Assembly functionality requires the Node server.

Configuration variables:

| Variable | Default | Purpose |
|---|---|---|
| HOST | 127.0.0.1 | Listening interface |
| PORT | 5173 | HTTP port |
| DATA_DIR | .data | Persistent private world directory |
| PUBLIC_ORIGIN | request host over HTTP | Exact accepted origin behind a proxy |
| SECURE_COOKIES | unset | Set to 1 with HTTPS |
| ADMIN_TOKEN | unset | Long random secret enabling admin endpoints |

Use HTTPS at the reverse proxy for an internet deployment, set PUBLIC_ORIGIN to its exact origin, and set SECURE_COOKIES=1. Keep the private data directory outside the published static tree. `.env.example` documents the settings; Node can read a configured file with `node --env-file=.env .build/scripts/serve.js`.

`GET /api/status` is a public health/configuration check. `POST /api/admin/live` accepts `{ "enabled": true, "seasonName": "Age of Storms", "mutator": "conducting", "announcements": ["The storm has arrived."] }` with `Authorization: Bearer <ADMIN_TOKEN>`. Maintenance disables new online battles; an already-issued battle can still be settled. Rules are captured at battle launch so configuration changes cannot alter an in-progress result. `POST /api/admin/analytics` with an empty object returns aggregate metrics using the same authentication.

Raw gameplay events are bounded to the last 1,000 per account. Daily activity retains 366 days for retention cohorts. Session duration is an estimate based on gameplay and minute heartbeats, excluding gaps over 30 minutes. Empty D1/D7/D30 cohorts report null rates. These are instrumentation outputs, not measured commercial retention claims.

## Content authoring and releases

Enable the battle journal/debug setting to expose the Alchemy Editor in navigation, or visit `/#editor`. Create element, reaction, status, enemy, relic or encounter templates, inspect effects, test an interaction, simulate a formation and inspect the complete event chain. The audit reports invalid references, duplicate concepts, dead ends, unused elements, unusually high effect power and bosses missing counterplay.

Preview installs a validated pack in the current local browser session. Online accounts cannot preview modified rules. Export a reviewed pack and append it to the array in `assets/content-packs.json`; validate with `npm run build`, run tests, and restart the server. Client and server install the same ordered packs. Pack validation checks every effect primitive, nested reaction condition, boss phase effect, status modifier, relic modifier and encounter reference before making any changes. Pack entry IDs are stable, updates increase entry versions, and recipe IDs are independent from their output element IDs. Alternate synthesis routes can therefore return to an existing element without duplicating its collection entry.

Candidate generation combines tags and effect vocabulary and explicitly marks proposals as requiring designer approval. It does not automatically publish generated reactions. Original hand-authored content remains the default; the 10,000-rule test verifies lookup scale rather than padding the game with filler recipes.

A release's content version is part of every replay. Old progression is migrated, but incompatible historical replays and pending battles are rejected/cleared instead of silently replaying different rules. Archive the old application build and data backup if historical replay playback is required. Remote mutators change runtime battle configuration. Reviewed content releases can also be published through the authenticated endpoint below without a restart.

## Publishing live content

`POST /api/admin/content` accepts `{ "pack": { "id": "release-name", "version": 1, ... }, "balance": { ... } }` with the same admin bearer token. The normal 64 KB request limit applies. Packs support elements, reactions, statuses, enemies (including boss phases), relics and encounters. Balance settings expose bounded combat and progression values; simulation timestep, execution limits and mastery thresholds remain fixed. For existing recipe cooldown changes, update the recipe definition itself.

1. Review and test the pack locally using the editor and tests.
2. Set `enabled: false` using `/api/admin/live`. Finish outstanding battles (abandoned issues expire after 24 hours).
3. Submit the release. Invalid definitions or balance values leave both stored and active content unchanged. A release is stored atomically before activation; entry versions and release versions must increase.
4. Re-enable the service through `/api/admin/live`.

`GET /api/content` exposes the ordered published release history and current version. Clients synchronize before online mutations, cache releases locally, and reinstall them before loading saves when offline. The server restores releases before normalizing account saves. Up to 100 releases may be stored before folding them into a new distribution. A new distribution needs a new base content version. Historical replay compatibility requires retaining its original distribution/content.

A minimal balance-only payload is provided in `examples/balance-release.json`. New executable effects, new UI screens or new kinds of content require a TypeScript release. Publishing data cannot run arbitrary code.

## Added progression and discovery systems

Each vessel can equip two ordered abilities. A ready ability replaces an elemental cast; wounded/unshielded conditions and cooldowns avoid wasting support actions. Campaign battles grant 10 vessel XP on victory and 3 otherwise, once per battle claim. Growth stops at level ten (450 XP). Fifteen vessel profiles define individual stat increments, idle motion, cast motion and timing; reduced-motion preferences suppress them.

Guild members may donate an elemental imprint for 30 mastery XP; an owning member studies it for 15 XP. Weekly missions require a contribution before reward claims. A hidden project accepts distinct stable pairings at one knowledge each and reveals its recipe after twenty contributions. Claim and contribution limits remain on the account when changing guilds.

The codex keeps the latest 200 distinct ordered reaction chains and encountered creatures. Chain paths come from causal simulation contexts, not neighboring log lines. Creature traits reveal after encounters; artifacts show acquisition state; lore includes owned elements and completed campaign memories. Continuation recipes close previously terminal graph nodes, and Mythic discoveries use the same bounded effect system.

## Discovery and build depth (0.5.0)

Specialization definitions can provide interpreted casting and kill effects. Ember stacks burns, Volcanic briefly roots targets, and Phoenix revives a fallen ally after a kill. These require compatible elemental tags and Evolution I; normalized combat ignores specializations. Definitions and cooldowns live in `src/data/systems.ts`. Combat resolves active specializations once per simulation rather than repeatedly searching the catalog.

`src/core/learning.ts` records unassisted discoveries, reactions used in a victory on their discovery day, actual elemental casts, victories with those casts, maximum causal-chain diversity and five tutorial steps. These facts persist separately from the latest 1,000 analytics events. Equipping an element or casting a slotted support ability does not count as an elemental cast. Replaying or retrying a claimed campaign battle adds no usage. A content upgrade discards stale unclaimed battle tickets before the next launch; stale finishes return a clear restart message and pay no rewards. Owned progress remains intact. Older saves retain their progress and infer the already-observable discovery, formation and battle tutorial steps; historical unassisted usage is not invented.

The daily rotation adds three goals: two distinct successful pairings involving a chosen starter element, winning with another starter element actually cast, and observing two causal reactions in one action. Each goal pays 25 gold, 3 knowledge and 5 essence once per UTC day. Client and server use the same commands; online commands use server time and persisted transactions. Maximum chain diversity remains available to quests after old codex paths are pruned.

The lab offers four-stage hints, an owned-element autocomplete list, every supported target condition, and preparation of known recipes. Mastery cannot be overridden by a laboratory scenario. Experiment history saves the complete scenario, so repeating a conditional experiment restores its requirements. Fully revealed hints can be reread without another charge.

Collection detail pages show evolution, specialization, casts, winning usage, observed chains and saved formations. Reports show actual healing/support/chain contributions and offer a follow-up experiment using the most frequent reaction's output without disclosing unknown recipes. The first-session guide advances through discovery, formation, battle, explicit report reflection and another independent discovery. Discovery chimes vary with elemental tags; rare reveals have stronger static glow and an explicit rarity label. Motion preferences suppress animation.

Seven collectible relics cover Common through Mythic; rarities identify artifacts rather than apply a global power multiplier. A Rare Storm Core can beat a Mythic Genesis Thread in a build needing additional chain targets rather than extra depth. Older packs without rarity remain supported as Common. Achievement rewards have their own persisted claim markers; the journal supports individual claims and claiming completed quests and achievements together. Experiment challenge authors earn 10 XP once per other solver's first valid solution. Solvers receive 20 XP and 3 knowledge; self-solutions add no creator bonus.

## Research and tactical choice (0.6.0)

Nineteen research studies span Elemental Science, Reaction Science, Combat Science, Alchemy, Creature Evolution, Artifact Research and Ancient Knowledge. Purchases enforce prerequisites and the Patient Scholar discount; the UI uses the same cost function and exposes prerequisite completion. Six new studies unlock four contextual recipes using existing elements, Renewal Pulse, the Echo Catalyst blueprint and a third ordered ability slot. The collection remains 87 usable elements with 128 recipes.

Laboratory scenarios cannot provide account research or mastery. Research conditions come from the player and are included in PvE combat snapshots. Hint selection omits recipes whose research is unavailable; prepared recipes display persistent requirements and correctly restore frozen targets. Blueprint crafting, ability assignment, saved formations, save normalization and replay validation enforce their respective unlocks. Replays reject invalid ability configurations rather than silently changing a battle. The third slot applies to the account formation in campaign and unrestricted trials; competitive combat clips both formations to their first two slots and omits research-gated recipes. Roguelite and loaned daily trials retain their own fixed progression rules.

Combat considers all matching recipes for each residue/affinity pair. Explicit player priorities precede even arbitrarily high content priorities. Disabled tags, cooldowns and chain guards allow the next eligible recipe from the same pair. AI planning and effect execution share the comparator. Tests cover alternate selection, cooldown fallback, disabled-tag fallback and bounded same-pair chains.

The Observatory shows the next unclaimed daily learning goal, ready quest/achievement rewards and the next accessible campaign objective. Quick battle uses the normal simulation and reward settlement, then opens the report. Pending launch protection avoids duplicate clicks; server-issued battle IDs retain their existing once-only settlement behavior. No new runtime dependency is needed.

## Guardian encounters and campaign conversations (0.7.0)

Five guardians now change combat rules as their health falls. The Molten King changes from Fire/Magma through Fire/Earth and Magma/Earth into an eruption; Wet and Frozen conditions interrupt its shield and eruption behaviors. The Plague Mother spreads Poison, summons a root guardian and strengthens its spores; Burn or Frozen conditions suppress the infection. The Tide Empress exposes a middle-phase Freeze vulnerability and a Shock-countered undertow. Tempest Titan exposes its core and gains Root-countered lightning arcs. Eclipse Sovereign opens a vulnerable mirror before gaining a silencing ward interrupted by Resistance Break or Frozen conditions.

`src/data/guardians.ts` defines these rules using the existing effect vocabulary. The engine keeps elements, immunities, behaviors and modifiers on combat instances. Phase element/immunity/behavior arrays replace the active rules; modifiers merge cumulatively. Crossing several thresholds in one hit records every phase in order. New immunities remove matching active statuses. A behavior's stable ID retains its cooldown across phase changes. Status counters and silence suppress ready behavior attempts; ordinary frozen-unit control also prevents casts. The same bounded trigger queues and summon limits apply. Shared unit validation checks descending thresholds, element/status/effect references, modifier limits, trigger types, unique behavior IDs and cooldown bounds before installing a pack.

Reports aggregate each unit's actual damage, damage received, effective healing, shield effects granted, damage absorbed, cleanses, kills, casts and reactions. Healing excludes overheal; shield grants use the actual shield increase rather than the accumulated shield total and exclude starting wards. Reaction support includes lingering healing, shield grants, cleanses and applied statuses. Phase transitions, observed behaviors and status interruption counts are aggregated independently of the capped event log. Reports display separate contributions without combining unlike measures into a single ranking. Support breakdowns are expandable, and narrow screens scroll the contribution table internally.

The battle preparation screen presents guardian field notes. Unit-name buttons open a timestamped snapshot of current elements, phase, immunities, statuses, residues and active cooldowns. The journal includes behavior and interruption events; reports show phase timelines and counter counts. Once settled, creature observations persist through local saves and authoritative account transactions. Old saves receive empty observations rather than invented history, and retries/replays add no rewards.

`src/data/scenes.ts` adds eighteen short illustrated conversations with six characters across the prologue and five regions. Unlocked preparations show opening dialogue; completed expeditions expose recovered dialogue in the report and lore codex. Recovery derives from campaign completion and needs no additional claim state. Locked regions hide future memories and cannot launch an expedition; region selection chooses the next accessible unfinished encounter.

## Run experimentation and build drafts (0.8.0)

Continuing run victories offer a temporary element, an upgrade/relic/passive choice and rest. Build categories rotate with the floor; choices use the run seed and current collection, so they persist reproducibly. When a collection is exhausted the draft uses remaining tools, and rest remains available even after every collectible is acquired. Recovery restores 35% health and revives fallen vessels at 60%. Eight-floor runs settle immediately at the final guardian; endless runs continue until defeat or retirement.

Drafted relics and passives become available to every vessel in that run. The run formation also exposes targeting, casting priority and three ordered reaction priorities. Only learned run recipes can be prioritized, and only drafted tools can be equipped. Account research, talents, growth, mastery and equipment remain absent from the run's battle configuration. Drafted tools are temporary; finishing or retiring returns learned reactions and accumulated resources once, while keeping the account formation intact.

The traveling laboratory uses the shared target-condition controls for statuses, health, shielding, enemy count and elemental tags. Its scenario persists across reload, but the floor determines its environment. Run experiments also honor suppressed reaction tags and consider eligible alternate recipes. Account mastery/research cannot be injected into the scenario. Modeling a target changes laboratory experiments without altering actual battle health or enemy statuses. Temporary recipes and ingredients are visible in the run journal and return to the permanent collection on settlement.

Endless Dungeon and Infinite Alchemy add a floor rule that changes every three encounters. The sequence derives from the run seed and floor, rather than wall-clock time. Infinite Alchemy also retains the expedition's weekly rule captured at entry; the floor rule avoids repeating it. Preparation explains both rules and the next transition. Battle configurations capture their merged modifiers, so a replay reproduces the launched rules even after the run advances. Boss affixes and scaling retain their existing independent generation.

Run normalization rebuilds reward offers, validates temporary collections and equipped tools, deduplicates priorities and sanitizes scenarios. Old saves gain empty tool collections/scenarios and retain their floor, health and discoveries. A content upgrade can refresh a pending draft; incompatible issued battle tickets/replays follow the existing content-version handling. Server commands block run formation/scenario edits while a run battle is issued, and concurrent settlement still pays once.

`scripts/run-balance.ts` samples four modes with recovery and drafting policies, two starting pairs plus the pinned daily draft. The 0.8.0 report covers 280 runs and 2,384 battles with reload normalization between battles. Samples stop at floor sixteen; capped endless runs are not declared complete. The results show that fixed builds and policies can fail, and do not establish optimal play, human pacing or long-term diversity. CI includes a smaller run sample.

## Build libraries and achievement facts (0.9.0)

`src/core/formations.ts` validates complete five-vessel snapshots against account unlocks before saving, replacing or applying them. Libraries retain ten named copies, reject blank or duplicate names and support rename/delete operations. Each save, replacement and application clones the team, avoiding shared mutable references. Save migration rejects inherited vessel keys, trims names and drops blank copies. The browser restores keyboard focus after library actions.

`learning.testedBuilds` retains the first one hundred canonical formation identities that take an action in a settled battle. Identities preserve vessel and elemental order, relics, passives, equipment, ability order, targeting, casting strategy and reaction priorities. Optional defaults and equipment property order normalize to one identity; names, seeds, mastery, research and other account power do not create new identities. Competitive configurations count their two active ability slots. Records are validated and bounded on load and survive analytics pruning or deletion of a saved formation. Older saves begin without inferred history.

Six new achievements cover secrets, one hundred discoveries, Fire-free victories, guardian Poison victories, five Legendary-or-Mythic discoveries and one hundred battle-tested builds. Legendary-or-Mythic eligibility is explicit because the catalog has three recipes at each rarity. Achievement cards display progress with accessible progress bars; claims use the existing shared, once-only reward mechanism. Illustrative five-hundred-discovery and ten-link targets exceed current catalog/depth and are not exposed as earnable goals.

Combat reports record allied periodic status damage by target and status using actual health loss after shields/armor. Guardian Poison progress requires a victorious battle, actual allied actions, a dead boss and positive Poison tick damage on that boss. A Poison affinity strike or damage only to minions is insufficient. Fire-free victories require Fire absent from the formation, casts, allied damage and triggered recipe ingredients/outputs. These aggregates remain available when the event log is clipped. Reports show lingering damage within vessel totals rather than adding it again.

`settleChallengeBattle` shares trial progression between the client and account service. It validates the content version, period and seed, then records a battle ID independently of its period reward. Defeats and already-paid trials can record facts once; repeating the ID or replaying the report cannot. Server snapshots preserve the launched formation when account choices change during playback. Server settlement refreshes achievements across all supported battle modes.

## Talent branches and laboratory notebooks (0.10.0)

Eighteen permanent talents form three-node paths in each of Alchemy, Combat, Discovery, Research, Exploration and Economy. Existing IDs, costs and cross-branch prerequisites remain compatible. Purchases spend knowledge only after checking prerequisites and ownership. Save/replay normalization retains complete prerequisite paths even when imported out of order; orphan advanced nodes are discarded. Production content validation rejects duplicate IDs, invalid costs, missing prerequisites and cycles.

Parallel Notes expands the laboratory notebook from one to two named prepared experiments. Saving, replacing and deleting use shared commands; loading restores ingredients, environment, statuses, health, enemy count, shielding and target tags without performing an experiment. Current account mastery and research always determine the result. Names are unique and bounded, notes are deep copies and import normalization enforces earned capacity and owned ingredients. The existing recent-experiment history remains independent.

Field Clues gives first campaign victories a seeded 35% chance of a stage-one clue for an unknown, unhinted reaction with owned ingredients and available research. It spends no knowledge and does not discover the recipe. Completed-encounter retries and replay cannot produce another first-clear clue. Unresolved clues persist in the laboratory journal and show only their earned hint stage. Gentle Guidance reduces paid hints from two knowledge to one. Discovered clues leave the unresolved list.

Focused Study adds ten percentage points to Patient Scholar's research discount, for 30% total. Applied Research grants three essence only on a new study purchased after learning the talent. Careful Crafting and Material Steward reduce gold and essence crafting costs by 15% and 20%, rounded up; blueprints and shard costs remain enforced. Displayed prices use the same functions as authoritative spending. First Survey awards three extra knowledge on first campaign victories; Guardian Bounty adds two shards on a first guardian victory. Campaign reports now show actual settled currency rewards, including essence/shards and talent bonuses. Progression perks use the account at settlement; combat talents remain captured at launch.

Reaction Conduit extends chain target reach. Reactive Ward uses the existing interpreted OnReaction passive event to shield the triggering allied vessel for half its attack, with a six-second per-vessel cooldown. Competitive normalization and loaned runs exclude this account passive. Unit inspection names its active cooldown; contribution reports retain its effective shield grants. Recursive Binding adds two depth levels while existing depth, per-action event and cooldown guards remain in force. With Chain Resonance, Genesis Thread and Echo Catalyst the developed PvE depth ceiling is ten; an authored ten-link achievement route has not yet been established.

Guardian checks cover changing rules, suppressed behaviors, retained cooldowns, support attribution, clipped-log independence, atomic pack rejection, scene gating and account restart/replay persistence. Run checks cover drafted tools, rest availability, scenarios, suppressed-rule fallback, floor mutations, migration, issued-battle protection and once-only retirement. Formation/achievement checks cover tactical snapshot cloning, library capacity/editing, unlock and malformed-reference guards, canonical build records, actual guardian status damage, clipped logs, trial-defeat settlement, migration, concurrent claims and restart persistence. Talent checks additionally cover prerequisite paths/cycles, rounded resource costs, non-retroactive research rewards, first-clear clue/bonus idempotency, source-only reaction wards and cooldowns, normalized fairness, notebook capacity and malformed-note repair.

Browser tests run in isolated Chromium desktop and Pixel 7 emulation contexts. They cover discovery -> equip -> combat -> rewards -> replay -> reload; all screens and horizontal overflow; all eight roguelite floors with reloads; online registration, guild creation, server rewards and sign-in; connected graph; content editor validation; offline reload; guided first sessions, full laboratory scenarios, daily/achievement claims, elemental audio startup and rare reveals with reduced motion, research purchases and branch navigation, third-slot persistence, catalyst crafting, home claims, quick battles and frozen-recipe preparation. They also cover campaign conversations, contribution reports, guardian preparation/inspection, observed phase persistence, Fire counterplay, replay reward protection and locked chapters. Run browser checks cover conditional scenario persistence, real relic/passive drafts, keyboard focus retention, rest selection and floor-rule replay. Library and achievement checks exercise keyboard editing, replacement/deletion, full libraries, Poison guardian proof, progress/reward persistence and trial-defeat replay protection. Talent browser checks cover all six branches, keyboard purchase/navigation focus, full prepared scenarios, the earned second slot, discounted prices, research essence, safe field clues and reloads. CI repeats tests, build and smaller campaign/run balance samples using the official [setup-node](https://github.com/actions/setup-node) and [checkout](https://github.com/actions/checkout) actions. [Playwright](https://playwright.dev/docs/intro) is justified by these browser checks.

Campaign tests find winning routes through all 63 encounters using three developed compositions; this demonstrates reachability, not that every build wins. The seeded balance report compares seven profiles across 5,600 battles, with a separate 280-run report for the run systems. Mastery power caps at level 10; deeper progression adds mechanics, specialization and collection choices.

The 5-10-hour campaign pacing, 60 FPS on physical mid-range devices, accessibility with actual assistive technologies, long-term build diversity, retention and fun require real-device and human playtesting. There are no purchased cosmetics, premium currency sales, payment integrations or gacha: those branches are optional in the specification, and cosmetic themes use earned gold. Operating ongoing seasons and a hosted multiplayer community requires an operator; release tooling and the local server are implemented here.
